# Compliance Big Bang Design (P1 + P2 + P3)

- Date: 2026-05-26
- Status: Approved (design phase)
- Scope: Governance-first big bang across compliance visibility, legacy path deprecation, and agent bootstrap standardization

## 1) Objective

Deliver a single governed sprint package that:

1. Turns raw compliance telemetry into operationally usable output (`view` + `export`)
2. Finalizes legacy-path deprecation execution policy with explicit adoption timeline
3. Standardizes agent bootstrap contract with `.sdd` authority precedence
4. Produces formal external-review compliance evidence

## 2) Architectural Direction

A governance-first sequence with hard gates between phases:

1. Foundation Governance
2. Capability Delivery
3. Deprecation Enforcement
4. External Compliance Pack

This order is intentional: it minimizes rework and ensures evidence generated by new CLI capabilities already reflects canonical governance boundaries.

## 3) Component Design

### P1 - Compliance Event Viewer

Core components:

1. Audit Query Layer

- Filter by `--since`, `--event-type`, severity, and source.
- Deterministic ordering to keep exports stable across environments.

1. Audit View CLI

- Human-readable output for quick investigation.
- Canonical use-case:
  - `sdd audit view --since 2025-06-01 --event-type VIOLATION`

1. Audit Export CLI

- Deterministic machine output (`csv` as first target format).
- Canonical use-case:
  - `sdd audit export --format=csv > compliance_report.csv`

1. Evidence Manifest

- Sidecar metadata artifact generated with export, including:
  - UTC timestamp
  - Applied filters
  - Governance fingerprint
  - Content hash

### P2 - Deduplicate Spec Paths / Legacy Removal

Core components:

1. Path Resolution Guard

- Q3 2026: `/legacy/**` accepted with structured deprecation warning.
- Q4 2026: `/legacy/**` blocked with explicit actionable error.

1. Migration Detector

- Detects residual legacy dependency and returns targeted migration guidance.

1. Breaking Change Ledger

- `BREAKING_CHANGES.md` records:
  - Q3 2026 deprecation
  - Q4 2026 removal
  - User impact and mitigation
  - Verification command/checklist

### P3 - Agent Bootstrap Standardization

Core components:

1. Bootstrap Contract

- `AGENTS.md` remains the cross-agent entry map.
- `.sdd/agent-instructions.md` is explicit authority anchor.

1. Claude Canonicalization

- Keep ADR-013 decision: root `CLAUDE.md` is pointer, not snapshot.
- Avoid introducing a second normative source at `.claude/agent-instructions.md`.

1. Drift Check

- Automated validation for mismatch between documented bootstrap contract and actual workspace bootstrap files.

## 4) End-to-End Flow

1. Agent bootstrap loads governance authority from `.sdd`
2. Runtime health/governance validated
3. `sdd audit view/export` runs with deterministic filters
4. Evidence manifest generated and bound to export artifact
5. Legacy path detector verifies no active dependence or emits staged enforcement result
6. External compliance pack assembled for reviewer consumption

## 5) Error Handling and Risk Controls

### P1 controls

1. Invalid filter values

- Non-zero exit code, deterministic message, corrective hint.

1. Missing/corrupt telemetry source

- Explicit failure; no silent fallback behavior.

1. Partial export failure

- No incomplete artifact publication if hash/manifest cannot be finalized.

### P2 controls

1. Staged enforcement timeline

- Q3 2026 warning mode
- Q4 2026 hard-fail mode

1. Documentation gating

- Breaking behavior changes require explicit `BREAKING_CHANGES.md` entry.

### P3 controls

1. Authority precedence

- `.sdd` always wins on conflict.

1. Bootstrap drift detection

- Fail validation if contract and runtime reality diverge.

## 6) Auditable Acceptance Criteria (Done de Governança)

1. AA1: `sdd audit view` and `sdd audit export --format=csv` support deterministic filtered output.
2. AA2: Export emits evidence manifest (filters, UTC timestamp, fingerprint, hash).
3. AA3: Legacy policy enforcement behaves by phase (Q3 warn, Q4 block) and is documented.
4. AA4: `AGENTS.md` is aligned with ADR-013 and bootstrap runtime behavior.
5. AA5: Test suites and governance validations are green.
6. AA6: External review package is generated and internally signed off.

## 7) Test Strategy

1. Unit tests

- Filter parsing and validation
- CSV serialization stability
- Manifest generation and hash integrity
- Legacy path resolution policy modes

1. Integration tests

- End-to-end `audit view` and `audit export` against realistic telemetry fixtures

1. Governance tests

- Bootstrap precedence and drift checks
- Legacy enforcement phase transitions

1. Regression tests

- Snapshot outputs for CLI formatting and deterministic ordering

## 8) External Compliance Evidence Pack

Target artifacts:

1. `compliance_report.csv`
2. `compliance_report.manifest.json`
3. `governance_validation.txt` (from `uv run sdd governance validate`)
4. `runtime_status.txt` (from `uv run sdd runtime status`)
5. `decision_trace.md` (ADR-013/ADR-014 + AGENTS/BREAKING_CHANGES linkage)
6. `external_review_checklist.md` (AA1-AA6 mapping)

## 9) Implementation Sequence (High-Level)

1. Finalize governance/document contract updates (P2/P3)
2. Implement P1 CLI capabilities under governed command model
3. Add tests and deterministic output guarantees
4. Generate compliance evidence artifacts
5. Run governance validation and package external review bundle

## 10) Scope Guardrails

In scope:

1. P1/P2/P3 as defined above
2. Documentation and governance traceability required for external review
3. Deterministic export and manifest integrity

Out of scope:

1. Unrelated CLI redesign
2. New telemetry backends beyond current runtime contract
3. Non-compliance feature work
