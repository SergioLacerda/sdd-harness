# Commit Protocol (P003)

**Policy:** P003 Mandatory Human Review
**Golden Rule:** *Agents propose, Humans dispose.*

---

## Why This Exists

AI agents can produce code that is syntactically correct but architecturally wrong. A human gate at the commit boundary is the only reliable way to catch this before it enters the repository history.

P003 makes the human review step **structural**, not optional. The agent's role ends at staging changes and explaining the diff. From that point on, the human decides.

---

## The Rule

| Action | Agent | Human |
|---|---|---|
| Write code / edit files | ✅ | — |
| Stage changes (`git add`) | ✅ | — |
| Suggest commit message | ✅ | — |
| Execute `git commit` | ❌ | ✅ |
| Execute `git push` | ❌ | ✅ |
| Merge pull requests | ❌ | ✅ |

An agent that commits or pushes autonomously is violating P003 — regardless of whether the change looks correct.

## Implementing in Seedlings

Every project generated by the SDD wizard inherits P003. To enforce it in your seedling:

### 1. Configure Your AI Agent

Add this rule to your agent's configuration file (`.github/copilot-instructions.md`, `.cursor/rules/*.mdc`, etc.):

```markdown
## Commit Protocol

This project follows P003 Mandatory Human Review.

- Suggest complete `git commit` commands with message — never execute them
- Never run `git push`, `git merge`, or force-push variants
- When work is ready: stage changes, explain the diff, present the command
- Human executes or explicitly approves before any git operation proceeds
```

### 2. Git Hooks (L1 — Local Barrier)

The `pre-push` hook blocks pushes in CI/automated environments. Install it:

```bash
cp .sdd/hooks/pre-push .git/hooks/pre-push
chmod +x .git/hooks/pre-push
```

The hook detects `CI=true` or agent-specific environment variables and exits with a non-zero code.

### 3. Branch Protection (L2 — Server Barrier)

In your GitHub repository settings, require:
- 1+ approving review on `main` and `develop`
- All status checks to pass before merging

This ensures no autonomous commit can be merged without human approval even if local hooks are bypassed.

## Agent Workflow

When an AI agent finishes a task, the expected handoff is:

```
1. Agent: writes changes, explains what was done and why
2. Agent: presents the exact command to review and execute
3. Human: reads the diff (git diff --staged)
4. Human: runs the commit command (or adjusts message)
5. Human: pushes when satisfied
```

### Example Handoff

The agent should output something like:

```
Changes staged. Suggested commit:

  git commit -m "feat: add timeout protection to test runner

  Added SIGALRM session timeout (300s) and per-test timeout (30s)
  via pytest-timeout. Prevents CI hangs from infinite loops.

  Co-Authored-By: Claude Sonnet 4.6 <noreply@anthropic.com>"

Review the diff with: git diff --staged
```

The human reads, adjusts if needed, and runs the command.

---

## Anti-Patterns to Avoid

| Pattern | Problem |
|---|---|
| Agent runs `git commit -m "..."` silently | Bypasses human review |
| Agent uses `--no-verify` | Disables safety hooks |
| Agent force-pushes to fix history | Destroys audit trail |
| Updating golden files in CI automatically | Hides real divergence |
| Agent amends a previous commit | Can overwrite committed work |

---

## CI Enforcement

The `sdd-validation` workflow checks that no governance policy is violated. If an agent manages to commit autonomously, the CI history still provides an audit trail via `Co-Authored-By` trailers.
